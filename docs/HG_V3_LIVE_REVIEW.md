## 如何打开具体位置

1. 先查看相应 run 的 `inputs.json` 和案例 JSON；由 `decision.report_path` 找 reports 下同名 JSON。`<RUN_DIR>` 是已脱敏路径占位符。
2. H 查看 decisions 的 block_id、anchor 与 location；A 交接可查看 h-to-a.json。
3. G 查看 findings 的 target/evidence；起止位置为 Python 字符偏移，不是字节。诊断 JSON 的 audit_report_path 指回原 G 报告。
4. 练习查看 checks 的 component、reason、location、lesson_location/evidence_location；如结果未通过结构校验，不存在放行报告。第二批补跑的原始结构化模型输出在 call-ledger.json 的 output 字段中。
5. 人工在 HG_V3_SIGNOFF.md 填姓名、日期、样例、打开的引句及同意/质疑理由。不能用本表的 AI 辅助意见代签。
